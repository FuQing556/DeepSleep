# 章节循环与失败检查点

## 当前闭环

`选角 → 按本段配置战斗 → 检查任务 → 停止刷怪并清残敌 → 节点揭示 → 恢复/购物/探索 → 双人准备 → 节点淡出 → 下一战斗段`

当前天空场景定位为原型/练习模板，暂定三个战斗段。前两段完成后进入休息节点，第三段完成后直接进入简单结算页；它不代表正式章节的 Boss、剧情或最终结算规格。

段数、时长、目标与敌人节奏读取本关 `MetaLevelDefinition.ChapterRunConfig`；不以本文的历史原型数量、秒数或击杀数覆盖各关配置。配置结构见 `23_DataDrivenCombatSegments.md`。

结算页展示完成段数、累计击败和实际战斗用时。最终段沿用直接结算：无奖励回收残敌/弹体，再提交已有战斗 Token；不额外要求清残敌。返回按钮通过 `GameSceneRouter` 退出本局、关闭传输并回到主菜单关卡选择，不重载旧场景。

## 失败条件

- 任一角色连续倒地超过配置的单人超时：该角色数据丢失，战斗失败。
- 两名角色同时倒地超过配置的全队超时：全队宕机，战斗失败。
- 本段倒计时结束时未达击败数或附加目标：任务未完成，战斗失败。
- 三条规则独立计时，先满足者生效；开始救援不会暂停数据丢失倒计时，真正复活后才清零。
- 清残敌仍属于战斗：停止新生成，但继续攻击、计击败数、发击败奖励和判断倒地失败。普通敌人清空后才关闭攻击并进入节点；不是刚开始清场就结束战斗。

## 检查点事务

节点离场开始时提交检查点，保存两名角色位置与生命、两份 Token 余额、强化等级、三选一内容、刷新次数、购买次数和随机节点序号。失败战斗中的击杀与 Token 收益不提交。

战败后同步关闭攻击、停止刷怪、以 `RunReset` 原因无奖励清场，取消特殊遭遇并回收敌弹/饭团。在配置的提示时间后，先只读验证整组检查点，随后恢复升级/钱包，最后恢复玩家精确生命和位置。验证失败只报一次且不开始部分恢复。已有上一节点时重新打开该节点，保留该检查点的商店，不再次回血覆盖精确生命；离开后重试失败的同一段。第一段失败恢复开局快照并直接重开第一段。

## 当前职责与接入

- `ChapterRunController` 是唯一流程提交者：开段、任务检查、失败、节点经济/恢复、检查点和结算。敌人列表从已验证的 Bindings 捕获，不另维护序列化敌池/刷怪器镜像数组。
- `ChapterCombatWorld2D` 从同一份 `LevelSceneBindings` 取得普通敌人及敌弹池，执行停止生成和无奖励回收；显式 `Rice` 对应网络世界引用的饭团池。
- 特殊模块登记在 `ParticipantComponents`，实现 `IChapterCombatLifecycle.StopCombat`；当前 World01 登记豆包驱动，原型场景为空数组。停止必须同步取消旧遭遇且可重复执行。
- `RestNodePrototypeController2D` 只负责节点表现、占用/交互、准备与离场，不再维护全关敌人池数组，也不自行提交钱包/检查点。
- 客机只根据 Chapter/Node 状态控制表现及交互门；不本地开段、结算钱包或恢复检查点。
- 场景退出由 Session 的显式 `SceneExitStarted` 通知章节停止战斗，普通会话通知不冒充离关。场景销毁前池的感知/奖励订阅继续保留，不逐段销毁池实例。

## 难度恢复规则

`ChapterRunConfig` 提供三种节点恢复方式：

- `FullRestore`：复活并回满，当前默认。
- `ReviveOnly`：只复活倒地角色，复活生命比例由配置决定；存活角色不回血。
- `Disabled`：节点不干预生命状态。

这些是运行配置，不与 UI 难度选择耦合；之后的难度菜单只负责选择对应配置资产。

## 编辑器快速验收

- `DeepSleep/调试/章节/完成任务并结束倒计时`：把本段目标设为完成并立即进入清场流程。
- `DeepSleep/调试/章节/任务不足并结束倒计时`：立即触发任务失败并检查收益回滚。
- `DeepSleep/调试/章节/直接完成三段原型`：把当前战斗视为最终段并直接验收结算页。
- `DeepSleep/调试/玩家/击倒 DeepSeek` 与 `击倒 Harness`：分别验证本关配置的单人和全队倒地限制，包括清场期间。
