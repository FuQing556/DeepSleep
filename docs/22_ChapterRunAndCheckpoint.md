# 章节循环与失败检查点

## 当前闭环

`选角 → 60 秒战斗 → 检查 10 杀任务 → 清场并进入节点 → 恢复/购物/探索 → 双人准备 → 节点淡出 → 下一战斗段`

当前天空场景定位为原型/练习模板，暂定三个战斗段。前两段完成后进入休息节点，第三段完成后直接进入简单结算页；它不代表正式章节的 Boss、剧情或最终结算规格。

三段的时长、目标与敌人节奏已经迁移到数据配置，具体结构和当前数值见 `23_DataDrivenCombatSegments.md`。

结算页展示完成段数、累计击败和实际战斗用时。最终战斗的 Token 会在结算前入账；“返回开局”通过重载当前测试场景彻底重置临时运行状态。正式关卡选择页完成后，再替换这一出口。

## 失败条件

- 任一角色连续倒地 10 秒仍未复活：该角色数据丢失，战斗失败。
- 两名角色同时倒地 2 秒：全队宕机，战斗失败。
- 60 秒结束时击败任意敌人少于 10 只：任务未完成，战斗失败。
- 三条规则独立计时，先满足者生效；开始救援不会暂停数据丢失倒计时，真正复活后才清零。

## 检查点事务

节点离场开始时提交检查点，保存两名角色位置与生命、两份 Token 余额、强化等级、三选一内容、刷新次数、购买次数和随机节点序号。失败战斗中的击杀与 Token 收益不提交。

战败后停止刷怪、以 `RunReset` 原因无奖励清场，并在 2 秒提示后恢复快照。已有上一节点时重新打开该节点；第一战斗段失败时恢复章节开始快照并直接重开第一段。

## 难度恢复规则

`ChapterRunConfig` 提供三种节点恢复方式：

- `FullRestore`：复活并回满，当前默认。
- `ReviveOnly`：只复活倒地角色，复活生命比例由配置决定；存活角色不回血。
- `Disabled`：节点不干预生命状态。

这些是运行配置，不与 UI 难度选择耦合；之后的难度菜单只负责选择对应配置资产。

## 编辑器快速验收

- `DeepSleep/调试/章节/完成任务并结束倒计时`：把本段目标设为完成并立即进入清场流程。
- `DeepSleep/调试/章节/任务不足并结束倒计时`：立即触发任务失败并检查收益回滚。
- `DeepSleep/调试/章节/直接完成三段原型`：把当前战斗视为最终段并直接验收结算页。
- `DeepSleep/调试/玩家/击倒 DeepSeek` 与 `击倒 Harness`：分别验证 10 秒单人限制和 2 秒全队限制。
