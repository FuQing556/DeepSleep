# DeepSleep 视觉尺寸与姿态切换实现规范

状态：已采用  
适用范围：玩家、敌人、弹体、技能特效、命中特效与后续所有 2D 战斗对象

## 1. 三类尺寸必须分离

1. **实体视觉尺寸**：角色和敌人的画面轮廓，由美术与策划共同标定。
2. **玩法判定尺寸**：碰撞体、伤害范围、索敌距离，只由玩法配置决定。
3. **命中特效可访问性尺寸**：只有攻击命中目标时生成的视觉反馈允许玩家调整。

禁止通过缩放带有碰撞体的根对象来实现“特效变大”。全局倍率只能施加到独立视觉子节点，或施加到纯表现对象的渲染计算中。

## 2. 当前基准尺寸

单位均为 Unity 世界单位下的可见包围盒，作为首轮手感基准，不是不可修改的常量。

| 类别 | 对象 | 当前基准 |
| --- | --- | --- |
| 玩家 | DeepSeek | 约 2.45 × 2.45 |
| 玩家 | Harness | 约 2.45 × 2.45 |
| 普通敌人 | 404 窗口 | 约 1.80 × 1.20 |
| 普通敌人 | 数据机械蛇 | 约 1.80 × 1.30 |
| 玩家弹体 | 初始饭团 | 约 0.61 × 0.61 |
| 敌方弹体 | 数据蛇红色子弹 | 约 0.46 × 0.31 |
| 玩家受击 | 数据蛇子弹命中 | 基础直径 0.78 |
| 玩家受击 | 404 撞击 | 基础直径 1.00 |
| 小型炮口特效 | 数据蛇蓄能炮口 | 基础直径 0.48 |

建议区间：

- 玩家主视觉：宽或高约 2.3～2.6。
- 普通敌人：主轮廓宽约 1.6～2.0。
- 精英敌人：主轮廓宽约 2.0～2.8。
- 高频小弹体：可见最大边约 0.35～0.75。
- 高频命中闪光：基础直径约 0.65～1.1。

最终尺寸必须以 16:9 实机画面、弹幕密度和碰撞可读性为准。

## 3. 命中特效尺寸选项

- 玩家允许范围：50%～500%。
- 配置初始默认可为100%；当前验收资产中玩家产生特效为300%，敌人产生特效为100%，后续以配置资产为准。
- 分为“玩家产生的战斗特效”和“敌人产生的战斗特效”两个独立倍率；按效果来源分类，不按效果落点分类。
- 计算规则：`最终显示尺寸 = 特效基础尺寸 × 对应来源类别倍率`。
- 不得影响子弹贴图、炮口、死亡表现、技能范围装饰、碰撞体、伤害宽度、索敌距离、角色或敌人本体。
- 子弹尺寸属于局内强化数值；死亡表现的基础尺寸必须依据死亡敌人的视觉轮廓标定。
- 500% 是实验上限；若实测造成严重遮挡，可在 UI 上线前降低上限，无需修改各个特效。
- 设置 UI 分别调用 `SetPlayerEffectScalePercent` 和 `SetEnemyEffectScalePercent`；持久化由后续本地设置服务负责，表现组件不得直接读写 PlayerPrefs。
- DS/Harness 的攻击命中与复活治疗加号属于玩家特效；404 撞击和机械蛇子弹命中属于敌人特效。复活收束圈用于表达固定进度，不响应特效倍率。

2026-09-08 治疗粒子基准：三层生成圆盘半径均为1.65，粒子中心随机分布于圆盘内部，不是仅沿圆周生成。收束圈外直径3.0；粒子基础尺寸后层0.15–0.23、中层0.17–0.26、前层0.15–0.25。治疗起步中层额外发射1个粒子；持续发射率仍分别为2.2/3.4/2.0每秒。粒子随机尺寸上下限同时乘玩家来源倍率，生成半径不跟随倍率变化。

## 4. 贴图导切换规范

同一对象的待机、瞄准、攻击、受击等状态贴图必须满足：

- 使用相同 PPU。
- 使用一致的 Pivot 语义和朝向约定。
- 在同一个主体 SpriteRenderer 上切换。
- 世界轮廓尺寸应接近；不得通过状态脚本临时补偿错误导入尺寸。
- 新状态在切换当帧立即完整显示，不能等待旧状态淡完。

数据蛇红眼图曾误设为 100 PPU，而常态为 512 PPU，造成 5.12 倍突变；现已统一为 512 PPU。

## 5. 单残影状态切换

残影是全游戏表现语言，不属于 Harness 或玩家专属技能。

统一规则：

1. 切换瞬间记录旧精灵、颜色、翻转和相对于实体根节点的姿态。
2. 新精灵在同一帧立即显示。
3. 旧精灵跟随所属实体平移；它保留切换瞬间的旧朝向、旋转和缩放，不继续接受新状态的动作变化。
4. 旧精灵从设定透明度逐渐淡出。
5. 每个实体只维护一个残影槽；连续快速切换时用最新旧姿态覆盖，避免叠出大量残影。
6. 残影不带碰撞体、伤害、阴影或状态逻辑。

公共算法为 `SpritePoseGhost2D`：复制相对姿态、按截取时透明度淡出、结束与停用清理。`SpritePoseTransition2D`、Harness 激光视图与玩家宕机视图均已接入，保留各自原有配置和渲染器，不重建节点。状态组件决定何时截取与切图，公共算法不决定玩法状态；新姿态同调用立即生效。Harness 攻击残影与宕机残影仍为原有独立槽，宕机先截取再清理攻击表现，避免清理覆盖死亡瞬间的姿态。

## 6. 节点层级规范

推荐：

```text
ActorRoot                 # 位置、刚体、碰撞、生命、状态
├─ VisualRoot             # 仅角色/敌人本体，可翻转和做动作倾斜
│  └─ Visual              # 主 SpriteRenderer
├─ PoseGhost              # 跟随 ActorRoot，保留旧状态的相对姿态
└─ MuzzleAnchor           # 独立于 VisualRoot 的缩放，只同步朝向位置
   └─ MuzzleVFX           # 炮口自身尺寸，不响应命中特效倍率
```

炮口不能直接嵌在被整体缩放的 `VisualRoot` 下再按固定尺寸制作，否则会发生父级缩放与特效缩放重复相乘。数据机械蛇已经改为独立炮口锚点。

## 2026-09-08 美术基准补充

用户指定现有 Harness 为全角色美术的画风与头身比例基准。DS 常态需要微调过大的头部，保留其蓝白配色、饭碗、服装与身份；不是照搬 Harness 姿态。候选见 `ArtProduction/20260908_PlayerStyleAndSword/README.md`，尚未获正式替换确认，现有生产素材与碰撞体保持不变。

## 7. 验收清单

- 状态切换前后主体轮廓没有明显尺寸跳变。
- 新状态立即出现，旧姿态跟随所属实体移动并淡出。
- 调整玩家/敌人受击倍率时，碰撞 Gizmo 和伤害测试结果完全不变。
- 50% 下关键信息仍可辨识。
- 500% 下允许夸张遮挡，但不得产生逻辑变化、对象池泄漏或碰撞放大。
- 实体移动时，已生成残影跟随实体根节点平移。
- 蓄力/开火期间锁定移动，后摇开始时恢复移动。
