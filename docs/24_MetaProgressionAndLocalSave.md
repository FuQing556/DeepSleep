# 局外成长、鲸元券商店与本地存档

场景生命周期与常驻服务见
[25_AppSceneArchitecture.md](25_AppSceneArchitecture.md)。

## 当前界面流程

```text
主页
├─ 开始游戏 → 关卡选择 → 游玩方式 → 单人选角 / 联机房间
├─ 鲸元券商店
├─ 背包
└─ 成就
```

天空测试场完成三段战斗后返回关卡选择，而不是返回最外层主页。
后续关卡目前显示为“暂未实现”，不允许点击。

## 三类数据不要混在一起

- `Token`：局内强化资源，进入新章节后重置。
- `鲸元券`：账号本地持久化的局外货币。
- `功德`：商店商品与背包物品，目前只有占位用途。

当前天空测试场首次通关奖励 10 鲸元券，重复通关奖励 5 鲸元券，
失败不发放。商店包含可重复购买的小功德、中功德、大功德，价格分别为
5、10、15 鲸元券。

## 为什么商品既有 ScriptableObject，又有预制体

`ShopProductDefinition` 是商品数据：稳定 ID、名称、说明、价格、图标、
是否可重复购买。`PF_UI_MetaProductCard` 是显示模板，只负责把数据渲染成
商店或背包里的卡片。这样新增商品只需增加一份数据资产，不需要复制一套
购买逻辑。

关卡同理：`MetaLevelDefinition` 保存稳定关卡 ID 和首通/重复奖励；
战斗细节继续由 `ChapterRunConfig` 管理。这是“局外目录”和“局内规则”两层，
不能为了省一个文件而合并。

## 本地存档

`LocalPlayerProfileStore` 是唯一写入口。它保存版本号、鲸元券余额、已拥有
商品数量、已通关关卡 ID、成就进度和已解锁成就 ID。存档写入：

```text
Application.persistentDataPath/profile.json
```

写入时先生成临时文件，再替换正式文件，并保留 `profile.backup.json`。
读档失败时会尝试备份；两份都无效才创建空档案。JSON 只保存稳定字符串 ID，
不保存场景对象或 ScriptableObject 引用，因此以后改图片、说明和价格不会让
旧存档失效。

存档格式当前为 v2。读取 v1 时会保留鲸元券、商品和通关记录，并补出空的
成就字段后升级；不会因为新增成就系统清空旧档案。

这是离线原型的可信边界：玩家可以手改本地 JSON。若未来做账号、排行榜或
付费商品，余额和购买必须改为服务器权威，本地文件只能作为缓存。

## 录制前清空存档

停止 Unity 播放后，选择 `DeepSleep → 调试 → 存档 → 清空本地存档（停止播放后）`。
确认后清空鲸元券、背包、通关与成就；下次从 Boot 播放即为新档。
工具先将主档、自动备份和临时文件归档到存档目录的 `DebugProfileArchives`，
再移除上述三个文件。恢复时停止播放，将归档中的原文件复制回存档目录即可。
不清除联机身份 PlayerPrefs。该菜单仅存在于编辑器。

## 联机奖励

战斗胜负仍由房主权威判定；收到完成状态后，每个客户端分别把通关奖励写入
自己的本地档案。奖励方法带一次性门闩，避免同一结算状态因网络重复广播而
重复发券。
