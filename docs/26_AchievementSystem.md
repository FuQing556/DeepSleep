# 成就系统

## 当前成就

| 稳定 ID | 名称 | 触发事件 | 隐藏 |
|---|---|---|---|
| `first_flight` | 最初的飞行 | 首次进入已实现关卡 | 是 |
| `first_clear` | 第一段旅程 | 首次完成关卡 | 否 |
| `first_revive` | 不要睡啦 | 首次成功复活队友 | 否 |
| `first_merit` | 一点功德 | 首次成功购买商品 | 否 |
| `flawless_clear` | 形影不离 | 全程无人进入倒地状态并完成关卡 | 否 |

成就目前不发鲸元券。以后高难成就需要奖励时，奖励类型应作为成就配置数据
加入，而不是在触发代码中硬编码；计划中的奖励方向是纯装饰品。

## 结构

```text
玩法/商店产生一次事件
        ↓
AchievementService.Report(triggerId)
        ↓
LocalPlayerProfileStore 一次性累计、判定、保存
        ↓
新解锁列表
   ├─ AchievementMenuController 刷新列表
   └─ AchievementToastView 按队列播放右下角通知
```

`AchievementDefinition` 是数据资产，只描述稳定 ID、名称、说明、隐藏状态、
触发 ID 与目标次数。业务系统不知道具体成就名称，只上报语义事件。因此以后
新增“复活 10 次”只需要新增配置并把目标次数设为 10，不需要复制复活逻辑。

玩法场景中的 `GameplayAchievementReporter` 只负责把复活系统事件转交给常驻
服务。它随玩法场景销毁，不会让 `AppRoot` 引用场景内玩家对象。

## 联机与无伤判定

战斗权威端维护“本局是否有人倒地”的历史标记，并随章节状态一起同步。
客户端结算时使用同步后的历史标记，避免只根据结算瞬间的生命状态误判无伤。

## UI 约束

成就列表是主菜单同级页面。解锁通知属于常驻 `AppRoot`，使用独立高层级
Overlay Canvas；卡片锚定手机安全区右下角，向内留出 70 像素，不占用 HS
的右上角色面板，并关闭射线拦截，因此不会挡住战斗按钮。
