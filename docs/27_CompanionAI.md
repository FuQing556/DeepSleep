# 双角色同伴 AI

> 前半部分保留原开放场地 AI 的设计和历史验证；2026-10-05 已接入节点目标与动态障碍导航，最新实现、验证边界见文末及 `docs/ImplementationEvidence/20261005_CompanionNavigation/README.md`。原文“目前无迷宫寻路”不再代表当前代码。

## 范围与边界

本轮接入现有 404、机械蛇、敌弹、DS 护航、HS 激光/光剑及自动救援。真人选 DS 时由 AI 控 HS，反之亦然。所有操作仍经 `ICommandSource → PlayerCommandDispatcher`，AI 不直接开火、扣血、清弹、恢复生命或改变位置。

当前没有倒地死亡倒计时、拾取物、Boss弱点/预告接口，所以没有实现这些对象的策略，也没有虚构“最后几秒拼命救援”。真实时机由实际生命、冷却、敌人位置/速度与救援触发器决定。未来 Boss/掉落属于新的感知适配与策略，不在这个版本伪装已完成。

## 结构与执行顺序

1. `CombatPerceptionBody2D` 是明确装配在敌人/敌弹预制体上的只读适配器，引用现有碰撞体与刚体。
2. 对象池创建实例时，向场景 `CombatPerceptionRegistry2D` 登记碰撞体索引。注册不是静态单例；不改原碰撞参数。
3. `CompanionBattleSensor2D` 每 0.125 秒通过 Physics2D 局部查询获取有界快照。256 个候选复用数组；不全场 Find、不逐帧 GetComponent。缓冲满时保守标记危险。
4. `CompanionCommandSource2D` 决定编队、战斗、避险、清场救援、靠近、停手引导。
5. `CompanionSteering2D` 评估目标方向、停止及八方向的预测风险、离目标距离和转向代价。预测使用相对速度，不把所有附近子弹都视作正在撞自己。这里是开放场地局部避险，不是绕迷宫寻路。
6. `CompanionCombatPolicy2D` 将决策转换为两名角色各自的按键；每个模拟刻仅生成一次命令并缓存，同一 tick 重读不会重复按技能。
7. `CompanionCommandRouter` 只驱动未被真人选中的角色。

## 目标与角色行为

- 目标分数包含敌种基础值、蓄力加分、靠近任一队友的危险、残血收益、距离代价和保持原目标加分。蛇基础3、404基础1；不是“永远最近”或“永远打蛇”。
- DS 保持持续自动攻击，按评分手动锁定；危险达到阈值或靠近倒地队友时按技能展开护航。遵守真实持续时间、次数与冷却。
- HS 锁定目标后不反复点击重启蓄力；附近聚集威胁或紧急情况时开启光剑，近处有目标/弹体时按住攻击。没有近处威胁一段时间后主动退出。
- 2026-09-09 修正：HS人机不在激光冷却期间预选；冷却结束后额外休息 `HarnessAimRestSeconds=0.25s` 再点选。DS未改。瞄准目标死亡/入池后保留最后有效位置完成本轮发射，不因目标消失而取消或卡住；详见28。
- 救援点不安全先清场；安全则接近。实际救援触发器提供目标后停止移动与攻击，交给已有自动救援引导。必要的防御按键仍能打断引导并执行，进度由原系统清空。
- 护航不会被当作永久无敌；AI不修改护航判定。风险是保守估计，不是保证永远无伤。

## 查看与调节

场景 `GameSimulation/AI_DeepSeek` 和 `GameSimulation/AI_Harness`：选中当前人机对应对象，在 `Companion Command Source 2D` 查看 Plan、Reason、Danger、Destination、Target。未接管的大脑不会运行。

配置：`Assets/_Project/Configs/Players/CFG_CompanionTactics_Default.asset`。

| 参数 | 初始值 | 含义 |
|---|---:|---|
| Decision Interval | 0.125s | 决策/感知间隔；不是技能冷却 |
| Prediction Seconds | 0.45s | 预测未来碰撞窗口 |
| Formation Offset | (-1.4, 1.4) | 相对真人的编队目标，边缘会夹紧 |
| Target Stickiness | 1.5 | 保留目标额外分，减少左右跳锁 |
| Rescue Danger Limit | 0.35 | 安全救援阈值，低血量更谨慎 |
| Emergency Danger | 0.65 | 紧急避险阈值 |
| Melee Enter / Attack Range | 3 / 4u | 战术出手距离，不改实际刀刃/剑气判定 |
| Melee Cluster Count | 2 | 附近聚集威胁的技能触发门槛 |
| Melee Idle Exit Seconds | 1.5s | 无近战目标后主动退出等待 |
| Harness Aim Rest Seconds | 0.25s | HS激光冷却后再休息一小段，仅人机使用 |

这些是初始战术调参，不是用户锁定的最终难度。没有改角色最大速度、HP、技能冷却、刀刃或敌弹的碰撞体。

显式装配菜单：`DeepSleep/设置/装配双角色同伴AI`。重复执行复用已有配置，不重置战术资产。算法断言菜单：`DeepSleep/验证/同伴AI风险数学`。

## 验收记录

以下为原开放场地 AI 的历史验收，不能证明它具备豆包迷宫导航或传送门目标行为；2026-10-05 的问题与后续方案见文末。

- Unity 实际编译、场景装配后 Console 无运行错误。装配前后预制体差异已审阅，敌人和弹体仅增加感知适配引用，未更改原碰撞数据。
- 最终编译后六项确定性风险/边界断言通过：迎面、远离、错开、静止重叠、窗口外来弹及边界容纳碰撞体。`git diff --check`通过。
- 选择 DS 后，HS 人机约19秒发射10次激光，编队移动并选中机械蛇。
- 最终代码重新进入 Play Mode，选 HS 后运行约28秒，DS处于Fight、手动锁定有效、目标为机械蛇；HS大脑为Inactive，Console零错误/警告。退出播放，未保存测试状态。
- 受控清场后令 DS 倒地，HS 经真实救援引导将其恢复到1血。
- 切换本地角色为 HS，令其倒地；DS 人机开启护航1次，并经救援将 HS 恢复到1血。
- 在 HS 附近放入两个404，人机开启近战1次，挥剑4次，目标离场后退出，保持3血。
- 初次长时间无人操作的自然战斗中双方曾倒地：AI遵守伤害规则，不代表可以保证自动通关。上述受控测试验证行为链，难度/成功率仍需用户实玩调节。
- Play Mode 测试中的刷怪暂停、清场、角色生命和临时后台运行设置均不保存到场景。未做真实触屏输入、长时压力/GC测量、Boss机制测试；不声称这些通过。

## 2026-10-05 AI 代理升级计划

用户反馈 AI 不躲障碍物，也不会主动靠近传送门。以下是当天较早的审查与规划；后续已实施的部分见下一节，不扩大到关卡重设计。

源码确认：CompanionBattleSensor2D 只接纳感知注册表对象；CombatPerceptionBody2D 目前仅支持敌人/敌弹，豆包气泡没有感知适配。CompanionSteering2D 是约 .45 秒预测的八方向局部避险，不是迷宫路径规划。CompanionCommandSource2D 默认目标为队友加编队偏移，没有传送门目标。RestNodePrototypeController2D 的自动准备只覆盖单机搭档和联机断线客人，主动托管不在此规则中。“走进门”与“点准备”是两个不同缺口。

建议实施顺序：

1. 节点目标与状态：提供显式节点目标接口，增加前往门、进入、停留/准备状态。真人表示要离开后搭档配合，避免提前结束休息；双 AI 用共同小队目标，避免相互跟随同一偏移。单机搭档与主客托管复用行为，在线决策仍由房主负责。自动准备是后续计划，本次不改；不顺带自动消费或选奖励。
2. 动态障碍导航：注册气泡等触发型危险体，按角色碰撞体扩张危险范围，并预测气泡下落；规划短程路线/中间路点，允许等待、侧绕、短暂后退。保留末端子弹避险，增加目标迟滞、进度检测和卡住重规划。不要只检测实体墙，不读取生成器秘密路线，不把障碍物塞进普通自动索敌。
3. 战术：把救援、DS 护航、HS 拆墙接到统一目标/风险判断；拆墙可选，不能以身体撞泡作为脱困方案。

验收覆盖 DS/HS 单机搭档、房主/客人主动托管、断线接管与双 AI；场景包含动态气泡、狭窄口、死路、门口停留、取消准备、托管切换和救援。记录碰泡次数、脱困时间、入门完成率，而不是只以“会移动/会攻击”为通过标准。双 AI 同偏移导致漂移是源码推断，尚未运行复现。

## 2026-10-05 实施：节点目标与动态导航

- `CompanionNodeGoal2D` 显式引用节点、会话、角色及碰撞体；真人在门内或已经准备时搭档配合走门，双 AI 共用门目标。用实际门 Box 与角色完整碰撞框判定进入；每固定刻检查停留/取消，不等低频寻路决策。取消准备优先于“还站在门内”，直到离门或重新准备才解除。
- `CompanionSquadAnchor2D` 在双托管战斗时固定进入双 AI 状态的共同编队中心，两角使用对称半偏移；恢复真人时失效。节点门目标和倒地救援优先。
- `CompanionObstacleRegistry2D` 独立登记气泡真实圆碰撞体、落速与生产者；池出入同步登记/注销，禁用/回收不参与感知，客户端不生成危险快照。它不是敌人自动索敌表。
- `CompanionNavigation2D` 只读可见危险快照，以角色真实 AABB 加 .06u 余量做连续圆角扩张检测。使用有界 A*、路点、1.2s 动态预测、目标迟滞、卡住重规划；局部无路可以等/侧绕/后退，绝不把隐藏迷宫保护通路当导航数据。4096 节点缓冲、256 泡、每次最多 768 展开；无路遵守 .35s 重规划节流，迫近危险例外。
- `CompanionSteering2D` 对路点方向、停止和八方向全/半速候选，用实际电机加减速和 fixedDeltaTime 检查“持有本次命令后制动”的轨迹。气泡碰撞是硬约束，不可用离目标更近抵消；已有重叠只允许逐步脱离，不作为常规穿泡方式。
- 救援风险包含气泡；路径受阻时先避险清障，不停在“想救但禁止攻击”的分支。近战可朝附近气泡挥刀，普通武器自动索敌不改。更深入的指定墙块拆除策略仍未做。

`CompanionNavigationInstaller.InstallAll()` 已显式装配 Gameplay_Prototype、World01，加入主机权威门控。版本标识 `20261005-companion-navigation-1`。**不改变自动准备、升级购买/奖励选择、关卡布局、角色速度/伤害/无敌规则，不出包。**

验证与未覆盖项见对应证据文档；算法测试、数值电机测试、真实手机/联机验收必须分开描述。
