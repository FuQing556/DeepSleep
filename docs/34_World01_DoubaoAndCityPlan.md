## 1. 设计来源与边界

设计顺序：角色梗 → 可玩的技能 → 视觉表现 → 章节归属。此前聊天中以职业、剧情安排角色的四世界分配未获采用。GPT-999 保留最强与因果设想，第四世界关底身份未锁定。

## 2. 第一世界的主题

- 互联网初期的希望，世界正在打开的感觉。
- 度过一天却一事无成的淡淡哀伤，不压过整体生机。
- 大城市的遥远、向往：远处高楼亮起，近处生活朴素。
- 旧电视、普通住宅、简单家具、旧电脑与天线等生活痕迹。

- 避免默认生成霓虹赛博都市、奢华神殿或废墟末世；不强行锁定公历年份。

## 3. 已确认的豆包遭遇

正常刷怪继续。豆包词墙从上往下持续掉落，形如比较密集、局部连接的俄罗斯方块，上面带文字。

豆包本体位于画面横向约 2/3、底边附近的一栋前景楼顶。第一波词墙到达屏幕底部后，本体出现并成为可攻击目标；出现后仍持续生成词墙。击败本体立即停止生成并清空所有词墙。本次遭遇不能随后自动重新启动。

“常态出现”表示可复用的常规机制遭遇，不是同一场无限复活豆包；以后是否再次出场由关卡编排决定。

遭遇流程：未触发 → 首波落下／本体未出现 → 首波抵达底部／本体出现 → 持续落墙并交战 → 本体被击败／立即清场 → 遭遇完成。

### 3.1 首波时机与落点

实现建议：用第一波的逻辑下落进度到达玩法区域底边来触发本体，不依赖某个词块仍然存活。第一波全部被提前打碎或碰掉，也必须按同一进度正常出场，不能卡死。

以固定玩法视野边界定义顶部、底部与横向坐标，不使用不同手机扩展出的装饰背景边界。跨屏幕宽高比维持相同可玩几何。

首版建议集中在中部：分组形状左右错开，留侧边通路与内部缺口；不是一条连续不可通过的整屏墙。生成点在可玩区域上方并有可读预告，不在角色身上实体化。

配置预留追踪落点变体：生成前采样一名玩家的位置并预警，确定后垂直下落，不能持续横追玩家。双人目标选择与轮换由主机确定。用户允许中部或追随方案，首版选择中部以便先验收密度与混战。

### 3.2 词块单位与交互

视觉组采用长条、L、T、阶梯等拼块，不要求严格四格，也不实现消行。每个带短语的矩形模块是独立耐久与接触消耗单位；同组共享下落速度，消除一块留下洞，不连带清除整组。

| 接触对象 | 当前设计口径 |
|---|---|
| 玩家本体 | 触发一次受击尝试，立即消耗该词块；已有无敌与护盾规则仍有效 |
| 怪物本体，包括 404 与机械蛇 | 对怪物结算一次伤害，立即消耗该词块；不能无条件删除仍有血量的 404 |
| DS 饭团 | 对词块造成伤害并被拦截 |
| 机械蛇子弹 | 被词块拦截、销毁 |
| HS 激光 | 对词块造成伤害，仍穿过并能命中后方目标 |

耐久暂保留用户先前提出的 10 HP／词块。注意：“一次接触消耗”与“子弹造成耐久伤害”是当前讨论采用的解释，不等于所有攻击一发删除；用户如意指一切命中均消失，必须同步取消 10 HP 规则，不能二者混写。

接触伤害建议初测 1，尚未锁定。玩家处于无敌或护航盾中，词块仍消耗，实际扣血／扣盾由现有伤害入口裁决。同词块同物理步只允许第一次有效接触触发消耗与伤害。相邻不同块仍是独立事件，但尊重玩家现有受伤无敌。

词块接触后立即消失，不再需要持续阻挡、挤出和间歇扣血；仍需检测接触，不可误写为完全无需碰撞计算。机械蛇沿现有移动意图行动，首版无需为了短命词块新增寻路。

建议：蛇弹撞墙不削减耐久；墙伤击杀怪物不归玩家击杀奖励、不发 Token，避免环境刷钱。上述奖励口径尚未由用户单独确认，实现前保留显式配置。

HS 剑身与剑气建议可伤墙；DS 溅射是否能隔墙波及目标、HS 连锁是否把墙作为分叉目标，属于尚待核对的攻击交互。默认建议：墙可受伤但不是自动索敌与连锁分叉的敌人目标；饭团直击墙仍可触发已有溅射，不额外发明障碍遮挡规则。必须通过实际现役伤害、索敌与几何代码审查后落实，不靠新增敌人标签凑合。

### 3.3 本体与清场

- 豆包本体有独立生命、可锁定目标与明确受击反馈；生命尚未确定，10 HP 不是本体血量。
- 身体露在楼顶上方，楼顶装饰不能成为遮住本体的无解实体墙。HS 能穿词墙点杀；DS 可以拆墙或利用缺口命中。
- 豆包战败事件同一权威处理内：停止计时生成、取消已预告未落下的组、禁用所有存活词块判定并回收，然后发布表现事件。
- 如保留碎片，仅作为无碰撞、无阻挡文字的装饰；不能用长淡出延迟“立即清空”。
- 失败回节点、重开、退出、断线、切场景时清除遭遇状态。节点快照需记录遭遇是否完成；重试恢复到对应检查点，不跳到下一段。
- 豆包遭遇参与该段完成条件，避免战斗倒计时到点把未完成遭遇直接切走；具体属于哪一段在关卡编排阶段配置。

## 4. 话术与素材

按用户提供的长话术选短语，保留讽刺性的连续堆叠。首批：最直接、最真相、最透彻、最尖锐、最深刻、最现实、最不绕弯、最不兜圈子、最扎心、最硬核、最干脆、最利落、最不墨迹、最不拖泥带水、最一针见血、最开门见山、最不铺垫、最不客套、最不寒暄、最不废话、最不赘述、最不冗余、最直白、最坦诚、最不加滤镜、最毫无保留。

句式可用“我给你——”起头，轮次末出现“终极回答：我没绷住”。收尾句不强制清场、不代表击败本体、不应每隔几秒重复刷屏。

绘制有质感的词块底板与必要连接件；文字用 Unity 文本独立覆盖以保持准确、清晰和可编辑。不同长度短语选择不同规格模块，不能把长句压成不可读小字。短语模块大小不受玩家／怪物命中特效倍率影响。

沿用已认可豆包外形参考；新增楼顶站立本体、说话状态、受击与退场所需最少状态。生成前使用项目美术规范，饱满异色底、本地抠图；本计划阶段不生成。

## 7. 开发顺序与验收

1. 核查现役伤害、投射物、激光几何、自动锁定、池、网络和章节快照入口，明确词块与敌人职责边界。
2. 完成黄昏战斗构图样张，摆角色／词墙／豆包楼顶／Claude 预留占区，检查视觉密度；节点做天台候选构图。
3. 制作确认构图的分层背景、豆包本体与词块底板；按项目规范检查透明、尺寸、字可读性与宽屏覆盖。
4. 实现词块耐久、接触一次消耗、攻击阻挡／穿透，全部由主机权威裁决，使用对象池与显式配置。
5. 实现连续落墙、首波逻辑进度触发本体、击败后立即清空、失败重试恢复；接入正常刷怪。
6. 接入黄昏到夜晚表现；Kimi 只预留事件入口，不提前制作其战斗。节点方案确认后再落地。
7. 验证单人 DS／HS、AI 托管与恢复、房主／客户端；查看双方词块、生命、豆包出场和清场一致。先编辑器／PC验证，是否打新手机包按用户后续安排。

重点验收：首波被提前全部消灭仍出本体；同词块同帧多人／多弹命中不重复消耗；词块池重用清空生命与接触记录；激光仍命中墙后目标；蛇弹不穿墙；怪物撞墙扣血且墙消失；豆包战败当帧与生成同帧不会残留新墙；失败重试不跳段；超宽比例无漏底；文字不被背景或伤害数字淹没。

所有速度、间隔、密度、形状库、落点、生命、伤害和时机阈值来自配置。联机主机发送生成身份、词组／形状、起始位置与时间以及消耗事件；客户端不自行随机生成或裁决碰撞。背景和词块移动不能改变玩家现有碰撞体调参。
