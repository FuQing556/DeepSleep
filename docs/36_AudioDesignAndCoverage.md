## 当前情况

`Assets/_Project/Audio` 已有 53 条短音和 3 条 20 秒环境循环，目录登记 42 个 cue。短音由 Kenney CC0 材质原料剪辑、滤波、包络与分层制作，环境是合成风及拟音颗粒的低音量候选，不是真实河流或城市录音。来源、哈希、可复现脚本和 8 组样本见 [素材记录](AudioProduction/20261005_CoreAudio/README.md)。[28 秒密度示例](AudioProduction/20261005_CoreAudio/previews/09_Density_28s.wav) 是离线编排，不是游戏录回。

Boot 持有一个播放器，24 个短声部（其中 4 个为危险提示预留）和两个环境交叉淡化声源。原生 AudioMixer 分为 UI、Player、Enemy、World、Ambience；短音单声道 PCM 解压预载，环境双声道 Vorbis 流式加载。主页和两关菜单有总音量、音效、环境滑杆，偏好只保存在本机。没有制作音乐、对白，没有改关卡数值或出包。

### 配置入口和验证边界

- `Assets/_Project/Audio/CFG_GameAudio.asset`：每个 cue 的 Clips、HarnessClips、Gain、MinimumInterval、MaximumVoices、Importance。更换素材或调音量不必修改玩法代码。
- `GameAudioService`：池、节流、声像、音量、环境与暂停；声音使用独立随机数，不改变战斗随机序列。
- `CombatAudioPresenter`：消费战斗事实；已有可靠激光/剑波/盾挡/命中通道复用，缺少的动作走消息 48。消息 49 只返回客人强化结果。网络协议为 5，内容版本 `20261005-core-audio-1`，不得与旧包混房。
- `SceneAudioPresenter`：阶段、节点、会话和成就提示。章节用 PhaseChanged，不靠逐帧轮询猜测短暂的通关状态。
- `CoreAudioInstaller.InstallAll()`：通过 Unity API 显式装配；`AudioUiInstaller` 只处理 UI。重复装配保留已调 UI 布局；目录默认混音会重写，手工调音后不要无目的重跑安装器。

Unity 编译、配置 297 项、场景/Prefab 绑定 172 项、播放管理 64 项、协议 1081 项、强化回执 25 项、隔离表现回放 10 项通过。两关四波和原有 16 站生命周期回归通过，最后一轮观察到 93 次被播放器接受的声音，两关各一次 Victory；存档及备份未变。详情见 [验证记录](ImplementationEvidence/20261005_CoreAudio/verification.txt)。这些检查不代表亲耳试听、手机扬声器、真实双设备联机或每个武器动作都已验收。

## 声音方向

DS 的主体是轻巧、柔韧的投掷与颗粒碰撞。参考当前米粒弹和护航表现，不做三角饭团咀嚼声，也不把普通攻击做成一串水滴提示音。手指拨动布面、少量干燥颗粒滚落、柔软表面接触可以作为拟音原料；保留短而清楚的接触点，不留黏腻尾巴。

HS 的主体是精密机构、薄金属张力和空气切割。激光应有收束、释放和短暂余振，近战应有方向与重量。避免尖锐锯齿音、夸张电流、电钻式连续高频和每招都带的大爆炸。阵列、连射、分叉增强同一声音的厚度和节奏，不因分支变多就无限加响。

UI 比战斗更轻、更近，操作听起来干净。DS 偏柔和的磨砂触感，HS 偏压低高频的小型金属机构；两套使用相同节奏和响度等级。沿用本机现有主题偏好：默认 DS，真人选择 HS 后保持，直到真人再选 DS。AI 托管、自动分配和远端玩家选角不改本机 UI 音色。角色武器始终按角色发声，不随菜单主题换音色。

黄昏城保留生活气息。河流在远处，水声应远、轻；近处是岸边草木和天台风，远处城市只有薄薄的生活底声，不做赛博电流底噪。天空测试场以开阔风声为主。背景轻微移动不等于角色高速飞行，不随每次镜头位移加入呼啸。

制作优先从有明确来源的拟音、录音和简单合成层做组合。生成式音频如要使用，只当原料候选：切掉无关铺垫、自动加的混响、伪人声和忽大忽小的段落，不能直接把整段生成结果当成品。“没有 AI 味”最终按材质可信、动作同步、重复耐听来验收，不能靠文件名或工具名称保证。

## 清单的读法

每行是一个需要处理的声音行为，不一定对应一张独立音频文件。同一族可以共用母素材；变体数量留到样本确认后决定。列为“静音”的行为也属于覆盖范围，是明确不响，不是漏做。

代码依据用 S01 等编号，见文末。各行描述设计目标；实际完成范围及未接入项以开头状态表为准。

## 把几种关键声音做细

声音层先在制作文件里编辑成成品，运行时大多数事件只播一个短 Clip，不把“精致”理解成每个事件实时叠五六个 AudioSource。

| 首批样本 | 主体和层次 | 试听重点 |
|---|---|---|
| DS 发射 | 很轻的拨动起音；柔韧投掷主体；少量颗粒短尾 | 不像吃东西、不像滴水提示；3 轮/秒有弹性，9 轮/秒仍清楚，不变成白噪声。 |
| DS 命中与溅射 | 命中紧实；溅射只向外铺开一点细碎尾声 | 空放和命中一听能区分；溅射变宽但不把小弹做成手雷。 |
| HS 激光 | 校准声末端收紧；发射一个短实核心；空气释放；很轻金属尾 | 高频不刺，手机扬声器也有主体；0.18 秒连射时尾巴不能越叠越厚。 |
| HS 三招近战 | 共用短柄/衣料起音；各自方向的空气主体；极轻收势 | 空挥有方向，打中才增加接触；剑波/回响保持从属关系。 |
| 受伤与盾挡 | 受伤偏实、盾挡偏弹；都保持短 | 满屏攻击里仍能区分“扣血”与“挡住”，但不惊吓玩家。 |
| 气泡破裂 | 干燥薄膜断开加很小的气流，不做湿黏口水声 | 单泡有触感，成片破泡听成一次由近到远的消散，不能像爆米花炸锅。 |
| UI 确认 | 轻触点、短回弹、可选极轻材质尾 | DS/HS 亲缘清楚；10 次连续点按不烦，没有每次都唱一个旋律。 |

变体不是随机大幅变调。高频主音先做 4–6 个真实细节变体，连续避免重复同一条；初试音高波动不超过约 ±2%，响度波动约 ±1 dB。警告、倒地、胜败的节奏保持固定。切头不要吞攻击起点，切尾做短淡出防爆音；禁止为每条音效各加一层长空间混响。

## 高频与混音规则

下面是待试听的初值，不是已验证的手机性能指标。

- 播放优先级：本机危险/倒地/救援完成和断线提示最高，其次队友危险、关键敌人预告、武器主动作，再到普通命中/击败、装饰、环境。不能让低价值碎响抢掉救援提示。
- 普通命中先按约 40–70 ms 聚合，同来源/同目标重复最先合并。每类命中先限 2–3 个同时发声；全体短音效先限 24 个，其中为关键提示预留 4 个。到上限先丢低优先级旧尾音，不排队几秒后再补播。素材和手机 Profile 结果出来后再调整。
- DS 每轮 1 个发射主音；HS 每次齐射 1 个主音；近战每刀 1 个主音。语义事件已有攻击标识时优先按标识合并，不能只按相同文件名误杀两名角色的动作。
- 一个命中先确定武器触感与目标材质，再组合为轻量结果。同次事件不把“武器命中、敌人受击、受击闪烁、伤害数字、掉钱”全都各响一声。
- 蛇蓄势是有限时长的声音，不建无限循环。近处即将打到玩家的威胁优先；若音量不够辨认，先减少装饰与普通命中声，不把所有蛇一齐加响。被省略的声音不能是唯一预警，视觉提示必须继续存在。
- 本机 UI 固定居中；世界短音按屏幕位置做有限左右声像，先限制在 ±0.6，重要警告保留居中成分。用当前相机实际视口，不硬套 16:9 安全区；手机多出的可见区不能产生过度偏耳或完全听不到的敌人。
- 同伴主武器可比本机低约 3 dB 作为起点，同伴倒地/救援警告不跟着弱化。攻击/命中音量不随伤害数字线性变大，第四波血多也不能让命中次数把整体持续推响。
- 混音以清楚的普通按钮确认为相对参考，环境明显低于交互，敌人普通命中低于角色受伤。先用耳朵匹配感知响度，不把所有短音一键归一到同一峰值。
- 关键受伤、倒地/救援时，可把普通战斗层短暂压低约 2–4 dB，再平滑恢复；只压必要层，避免每次攻击都让音乐抽吸。输出留余量，满升级+豆包清场不能削波。先以成品短音峰值不高于 -3 dBFS 为制作参考，最终主总线需实际录回检查，不能用单条峰值代替全场混音检查。
- 单机暂停、联机菜单、休息、失败、结算、切后台分别有音量/暂停策略。过场淡化与 UI 使用不受 Time.timeScale 停止的时间基准；退出清理循环和延迟声。恢复焦点只恢复应有的底声，丢弃过期战斗事件。

## 接入只做必要部分

建议采用 Unity 原生 AudioSource 和 AudioMixer，不引入第三方音频中间件，也不另造一套玩法事件总线。

1. Boot 显式装配一个持久的播放入口、小型短音源池和独立环境/持续声槽位。场景引用显式注入，最多一个有效 AudioListener；不在每个敌人、每颗子弹的 Update 里找全局对象或临时加 AudioSource。
2. 一个声音目录记录：标识、变体、输出组、音量、有限随机范围、并发/最小间隔、优先级、循环及清理方式。每个调用点只传已确认的声音语义、位置、来源和必要动作标识。先不增加多层继承、外部 DSL、热更框架或通用规则引擎。
3. Mixer 分组先用 Master、UI、Player、Enemy、World、Ambience、Music。玩家设置提供总音量、音效、环境、音乐；角色语音还没做，不摆一个无效滑杆。音量偏好只保存在本机，不随存档回滚或联机房主改变。现有项目没有完整音量设置页，这是待实施项。
4. 短高频 Clip 优先预载并考虑 Decompress On Load；长环境/音乐按实际长度考虑压缩或 Streaming。世界定位短音通常做单声道，环境可做立体声。不要将所有文件一律设为同一种加载方式。Unity 对加载模式和平台覆盖的定义见 [Audio Clip 导入设置](https://docs.unity3d.com/6000.0/Documentation/Manual/class-AudioClip.html)。
5. 混音状态的淡入淡出可用 Mixer Snapshot，游戏内仍需显式管理循环寿命和暂停范围；Snapshot 不能代替退出清理。Unity 提供限时过渡接口，见 [AudioMixerSnapshot.TransitionTo](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Audio.AudioMixerSnapshot.TransitionTo.html)。

拟定资源位置：`Assets/_Project/Audio/SFX/{UI,DeepSeek,Harness,Players,Enemies,Flow}`、`Audio/Ambience`、`Audio/Music`；目录/混音配置归 `Configs/Presentation/Audio`，源录音、剪辑工程、试听组合和来源许可记录归 `docs/AudioProduction/<批次>`。只有确认过的成品进 Assets。这些目录本轮没有创建。

母版建议 48 kHz、24-bit WAV，保留干声和可重混层；长循环另留干净接缝版本。真实规格按原始素材质量确定，不把低质量素材升采样冒充高质量。已有 Git LFS 规则覆盖 WAV/OGG/MP3/FLAC/AIFF；来源、作者、许可和修改记录一起保存，不使用来源不明的游戏拆包素材。

## 联机与回滚不能漏

音频本地播放，玩法仍由现有主机裁决。不能只给房主的伤害回调接声音，也不能把所有音频命令再单独广播一套造成重播。

| 语义 | 单机或房主 | 客人 | 防重与恢复 |
|---|---|---|---|
| 普通按钮、复制、当地面板 | 本机有效 UI 操作 | 本机有效 UI 操作 | 不联网；主机购买确认前只有轻触感，不提前播成功。 |
| 激光、剑波、盾挡 | 现有权威动作语义 | 现有 NetworkWeaponChannel 接收表现入口 | 汇入同一声音路由；不能同时监听动作和特效 Instantiate 各播一次。 |
| DS 发射、挥刀起势、技能开关、角色状态 | 真实动作/状态边沿 | 逐项检查现有消息是否有可靠动作边沿 | 当前 DS 弹体主要走快照，快照新增实体不等于准确发射时刻。缺的只补紧凑动作标识，不从每帧位置变化猜。 |
| 伤害与敌人击败 | 实际接受伤害或 Defeated | 已同步反馈事件，缺死亡原因时需补语义 | 不能从 HP 下降/对象消失直接推断所有音效，初次快照和池复用会误报。 |
| 豆包、气泡 | 前奏/现身/破裂原因/完成边沿 | 审核 DoubaoEncounterNetworkChannel 可提供的边沿和原因 | 单泡消失可能是自然回收或全场清除；需要原因区分，再谈音效映射。 |
| 购买、准备、结算 | 实际状态确认 | 主机确认结果或明确状态变化 | 一般余额/商店全量快照不足以证明“本次购买成功”；必要时补结果序号。 |

实现前逐条核对消息当前已有的身份字段；需要补去重时使用本局/本段重试代次、实体池复用代次与动作序号。不要假设所有网络消息已带同一种 AttackId，也不要为纯本地 UI 建网络序号体系。失败、切关和重连清掉旧持续声与旧段队列；重连初始状态静默建立，仅恢复当前还在持续的校准/救援/环境，不补播历史击杀和奖励。

AI 托管只改变命令来源，不能改变播放权限或换一套音频订阅。验收必须同时包含 DS/HS、电脑/手机、房主/客人、托管前后，不能因单机有声音就宣布联机完成。

## 已发现的接线风险

- 米粒 HitConfirmed 包含直击和溅射逐目标命中，直接全订阅会重复响。需保留爆心与伤害目标的区别。S09
- 护航 Ended 既可能是耗尽/到期，也可能是倒地或取消，需要结束原因才能选择声音。S08
- 蛇进入 FirePose 不证明弹体池租借成功；开火音应在真实成功出口。S12
- 气泡 Popped 的布尔值主要区分冲击效果，不足以表达打碎、无敌碰泡和 Boss 清场全部原因。豆包败后逐泡 ClearWithEffect 不能逐泡出声。S16
- 普通敌人回池不一定是击败；奖励本来也只接受 Defeated 且非 suppressKillReward，声音应同样区分。S12、S18
- 钱包/商店/角色通用 Changed 事件也用于网络还原和重试恢复，不能把它们直接当“赚到钱、买到东西、复活成功”。

这些是音效接入时要补清楚的事件语义，不是本轮已经修复的 Bug；不得趁音效制作扩展为战斗框架重构。

## 制作与验收顺序

第一批做材质样本，先听 8 组：DS 发射、DS 命中/溅射、HS 激光、HS 三招近战、角色受伤/盾挡、气泡破裂、双主题 UI 确认、黄昏环境。每组先给少量不同方向，不一次铺满全表。交付单音试听，加 DS 满攻速/扇阵和 HS 连射/多端口的约 20–30 秒混合示例；样本没有通过就不量产同族变体。

确认材质后做完整战斗族并接入两关。随后补 UI/联机/休息/胜败、环境切换和音量设置，最后再处理音乐。完成标准是上面每一行都有成品绑定或明确静音决定、主客机触发与清理证明；不是数文件数量。

验收清单：

- 普通与满升级 DS 连续射击、扇阵、多目标校准、溅射；HS 校准取消、阵列、连射、最大分叉、三刀、回响、清弹及技能中途停止。
- 真正扣血、无敌拒伤、护盾挡击、最后一层/自然到期/倒地取消；两人同时受伤、倒地、救援取消及成功。
- 404/蛇实际出生、命中、击败与无奖励回池；多蛇同时蓄势/发射、弹体撞泡/撞人/被清掉，不误播重复受伤。
- 四波豆包、气泡成片打碎和 Boss 击败全清；测试最大气泡数量，不允许清场声暴涨。
- 两关完整四波、三次休息、买卡/免费及付费刷新/余额不足、设施拒绝、准备取消/双方出发、第四波失败回滚和最终结算。
- 主页双主题、两关入口、各菜单、鲸元商店、背包、成就、选角、主机开房、加入失败/成功、托管、意外断线、主动离房。
- 单机/联机菜单、确认框、退出、重试、切后台/恢复，循环不残留；Time.timeScale 为 0 时 UI 仍有反馈且战斗不误补播。
- 手机超长屏、PC 宽屏；手机扬声器、耳机和单声道；低音量能分辨危险反馈，连续一局不疲劳，不靠低频震动撑全部力度。
- 实机记录峰值、短音源数量、被合并/丢弃的事件、音频 CPU 和内存；关音乐与开音乐分别听。同机没有爆音不代表手机通过。
- 电脑与手机分别作主客机，DS/HS 换位，AI 托管前后；首入、重试、重连不遗漏关键声，也不补播旧声音。
