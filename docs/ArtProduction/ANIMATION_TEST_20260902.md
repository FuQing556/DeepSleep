# 动画生成试验记录｜2026-09-02

> **已被同日用户决策取代**：正式生产采用“一种语义状态一张主图 + Unity Transform/颜色/VFX 动效”。本页两张八帧图仅保留为生成能力与动作分镜试验，不再指导生产，也不得进入 Unity 正式 Sprite Sheet。

## 目标

以已通过的 DeepSeek 鲸鱼娘设定为身份锚，试做一次完整的 8 帧 `TapRise` 点按上升动作，验证生成式图片能否直接交付 Unity Sprite Sheet。

## 动作节拍

读取顺序为左到右、上到下：

1. 中性悬浮。
2. 下沉蓄力。
3. 手臂与鲸鳍耳开始下压，鲸尾卷曲。
4. 最强下压，头发和裙摆受气流抬起。
5. 上升到最高伸展姿势。
6. 手臂回收，头发与围裙保持惯性。
7. 鲸尾过冲后回摆。
8. 回到接近中性悬浮姿势。

## 验收结论

- 通过：八帧数量正确；动作起承转合可读；角色配色、服装与鲸鱼特征基本统一；作为动画分镜底稿有价值。
- 未通过：没有真实 Alpha；网格不是 320×320 等尺寸生产格；身体锚点存在明显漂移；第五帧视角偏正；鲸尾弯曲与鳍耳细节存在帧间变形；首尾帧不能直接无缝循环。
- 结论：现阶段图像生成器可以提供 4–8 帧动作分镜和关键姿势，不能不经整理直接交付正式逐帧动画。

## 当时拟定策略（历史，不执行）

以下条目记录试验当时的判断，现由 `14_DecisionRegister.md` 的 DR-015 覆盖：

1. 先锁定一张透明、正交、固定 Pivot 的角色母图。
2. 将头、躯干、前后手臂、前后鲸鳍耳、头发、围裙和鲸尾拆为独立透明部件。
3. `IdleFly`、`HoldRise`、`Fall` 优先用 Unity 2D 骨骼或 Transform 动画完成，确保轮廓不漂移。
4. `TapRise` 只保留 4 张真正改变剪影的关键帧；需要八帧时，由部件插值补出过渡帧。
5. `Hurt`、`Execute`、`Victory` 等无法靠部件摆动表达的动作，再绘制 2–6 张独立关键帧。
6. 任何正式 Sheet 必须为 320×320 等格、固定 Pivot、真透明 Alpha，并在缩到游戏尺寸后复验。
