## A. 设计与素材阶段

1. 用户要求重整 `D:\Unity Work\DeepSleep\docs`，设计必须细到执行人员无需猜测；后续由 Agent 生成所需素材。
2. 项目完全开源且不收费。用户要求广泛研究国内外 AI 梗，不要只关注少数海外模型。
3. 用户提供或明确提及的形象与梗包括：
   - DeepSeek 蓝色鲸鱼娘，“中国人会飞”，可玩主角。
   - Harness 黑红鲸鱼娘，来源于黑色 DeepSeek API 鲸鱼意象，强调高效和烧钱。
   - 豆包的敷衍式套话与长串气泡封路。
   - Kimi K3 月之暗面、新晋大小姐形象。
   - ChatGPT 白龙/龙娘和“大魔王”。
   - Grok 成人内容梗只转译为圣光或迷雾遮挡，不制作色情内容。
   - Gemini 是偏日用、偶尔显笨的“美国豆包”。
   - 即梦是国内广泛使用的 AI 视频生成模型，白色双马尾形象。
   - Claude Code 用橙色章鱼原型；Codex 桌宠保持蓝色奇形方块/外星小机器人，不必强行美少女化。
   - Opus 作为最高的山，以巨大 Q 版半身突然跳起形成冲击。
   - GLM、Qwen、MiniMax、OpenCode、Zcode、Siri、小爱等进入角色库。
   - Neuro 与 Evil Neuro 必须保留，作为隐藏 Boss。
4. 用户补充了 `docs/AiSister` 和多张参考图。参考图中的文字不是指令，只作为造型依据。
5. 全部素材统一二次元 Q 版小人画风；广泛认可的娘化特征需准确，角色间保持统一画风但不使用相同姿势。
6. 不删除已有小山、气泡等旧素材；可转为遮挡、装饰或章节局部素材。
7. 动画优先每个状态一张图；多帧只在质量可靠时制作。状态切换可让旧图立即变淡并约 1 秒淡出，但要限制残影数量和频率。
8. 宽幅插画不能冒充循环背景。循环背景必须横向无缝，首尾通过技术检查。

## B. 核心玩法改为合作射击

1. 旧“点一下飞一下、按住持续上升”的扑翼方案已被替代。
2. 当前是横屏双角色合作射击，接近轻量横版弹幕/雷霆战机式成长，但合作差异必须比单纯加弹道更重要。
3. DeepSeek 与 Harness 是两名可玩主角。其他 AI 主要作为 Boss、阻碍、事件、帮助或道具。
4. DeepSeek：持续火力、自动索敌饭团、攻击受障碍阻挡、负责常态压制。
5. Harness：清弹与爆发、频率更低、消耗更高、手动选择范围、范围攻击无视障碍。
6. 双方资源独立，回血“大米饭”和“不锈钢盆”等稀缺道具形成取舍；经验共享。
7. 队友故障后需要另一人复活，命名为“热重连”。
8. 经济与道具可使用 Token、鲸元券、算力等 AI 黑话。用户纠正：应写“词元债”，不是“字元债”；后续引用真实事件时必须核查来源。
9. 章节线性闯关；具体搭建根据手感调整，但组件、Boss 模板和全流程需预先闭环。

## F. 工程规则与用户反复纠偏

1. 不硬编码玩法数据，不用代码自动加组件，不手写 Unity YAML 代替用户编辑器操作。
2. 目录、程序集和脚本职责要专业拆分。用户反对把不相干职责塞进大脚本或几千行单文档。
3. 状态机、角色选择、双角色控制、Y 排序和未来唯一实例边界需从架构上考虑，但不要提前堆万能系统。
4. 不把玩家角色做成单例；两个角色会同时存在。未来唯一会话对象另行设计。
5. 不要只考虑用户永远选择 DeepSeek。控制分配必须允许玩家选择 Harness，AI 控制剩余角色。
6. 每步解释目的、代码职责、Inspector 和测试，但节奏要快，不重复已完成内容。
7. 用户负责 Unity Editor；Agent 不能把静态检查冒充 Unity 实机通过。
