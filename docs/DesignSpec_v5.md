## 1. 一句话产品定义

DeepSeek蓝白虎鲸娘与DeepSeek Harness黑红虎鲸娘在AI网络梦境中横向飞行并共同作战：DeepSeek用不断成长的高频饭团火力压制敌人，Harness用受预算限制的清弹领域化解危机并制造爆发窗口；单人时另一角色由本地AI控制，双人时Windows与Android玩家可跨端组队。后续人物动作严格以已导入游戏的两张角色Sprite为视觉母版，不根据图标重新设计人物。

## 2. 当前锁定的产品规则

1. 2D横屏横向卷轴射击，角色在16:9逻辑区内自由二维移动，不受重力和扑翼输入约束。
2. 蓝色DeepSeek与黑红Harness始终同时出战，不再拥有两条互斥单人路线。
3. DeepSeek是常态输出核心：高频、自动索敌饭团、可见火力成长、会被真实障碍阻挡。
4. Harness是清弹与爆发核心：低常态火力、手动选区、高耗能、清除可清弹、范围攻击穿过普通障碍。
5. 两个角色必须形成合作闭环，不能只是换皮武器；标准难度中任一职责长期缺席都会明显增加压力。
6. 单人选择一个角色后，另一个由AI接管；AI与真人使用相同命令、资源、碰撞和技能规则。
7. 双人每台设备控制一个角色，角色不可重复；支持Windows↔Android、Windows↔Windows、Android↔Android。
8. 双人入口包含私人房间和快速匹配。私人房间允许房主先选角色并分享房间码；快速匹配先选角色，只匹配互补角色。
9. 首版仍采用线性章节闯关，不以无尽随机为主流程。
10. 首发本地存档；公网联机需要房间和中继服务，但不建立账号成长、聊天、公会、付费或排行榜。
11. 资源热更新进入正式架构；C#代码热更新预留并在联网切片稳定后接入。
12. 当前目标编辑器改为Unity 6.6（6000.6.0f1）；这是Hub面向新项目推荐的正式受支持版本。由于旧工程几乎没有玩法实现且玩法已整体改版，新建通用二维（Universal 2D）工程，不做原地升级。
13. 角色生命耗尽后进入“模型宕机”并显示角色睡眠姿态；存活队友进入以倒地角色为中心的救援范围、停止主动操作后自动执行“热重连”。移动、主动攻击、技能、受击或离开范围都会中断并清空进度；双人同时宕机或重连窗口耗尽才判定失败。
14. Token作为共享章内经验；达到升级节点时双方各进行一次本角色强化卡三选一，每章重新构筑。生命上限属于可选强化，复活生命为`max(1, floor(最大生命值 / 3))`。鲸元券只用于局外侧选协议和收藏，不购买永久数值。
15. 词元债是主动透支额外拓展产生的个人风险标记，通过下一战斗段的催收协议偿还；不作为第四种拾取货币。名称取自现实Token（词元）算力工厂科创债，具体玩法为本作转译。

## 4. 游戏模式流程

```text
启动与版本检查
→ 主菜单
   ├─ 单人游戏 → 选择角色 → AI接管另一角色 → 章节选择 → 战斗
   └─ 双人游戏
      ├─ 快速匹配 → 先选角色 → 匹配互补角色 → 准备 → 战斗
      ├─ 创建私人房间 → 房间码/先选角色 → 等待加入 → 准备 → 战斗
      └─ 加入私人房间 → 输入房间码 → 选择剩余角色 → 准备 → 战斗
→ 结算、本地保存、重试或返回房间
```

## 5. 角色差异底线

### 5.1 DeepSeek

- 即使没有技能资源也保持强常态输出。
- 普通饭团只自动搜索当前朝向前方且可见的目标，不因身后敌人自动翻转；玩家手动锁定身后目标时才连同视觉和发射点一起转身。
- 局内拾取会让饭团射速更快、弹道更多、弹体更大，并逐步加入穿透/连锁等形态。
- 主动能力围绕集中火力和小范围护航，不获得无限制全屏清弹。

### 5.2 Harness

- 常态攻击弱且低频，不能长期替代DeepSeek。
- 普攻为手动点击目标、显示细瞄准线后结算的低频终端激光；它负责精确补刀与少量预算回收，不负责持续压制或清弹。
- 依赖预算能量手动释放大范围清算，先清可清弹，再结算爆发伤害。
- 成功清弹触发被动“预算回收”；次技能“预算透支”提供一次紧急近身清弹，代价是随后进入429限流。
- 升级强化清弹范围、储存、余波和爆发质量，但始终保留资源空窗。

### 5.3 合作检验

- DeepSeek持续输出建立伤害和共鸣；Harness等待高价值弹幕并创造安全/破绽窗口。
- Boss至少轮换持续压制、危机清场和破绽爆发三个职责阶段。
- 一方宕机可由另一方热重连；双方同时宕机或重连窗口耗尽才失败。
- 救援显示为“热重连”，存活者进入范围并停止主动操作后自动引导；移动或主动操作中断并清空，本帧技能输入仍应执行。真实网络断开由AI接管，不能与模型宕机混为一谈。

## 6. 联机边界

- 采用两人Listen Server/Host结构，房主设备承担权威模拟。
- 主机决定伤害、敌人、Boss、掉落、技能消耗和章节进度。
- 客户端上传角色指令，本地预测移动，主机快照校正。
- 客人断线由AI接管；重连后在安全点交还。首版不做房主迁移。
- 战斗逻辑不依赖平台按键，因此电脑和手机可进入同一房间。
- 公网服务通过项目接口隔离；国内可达性实测前不把玩法绑死在单一云平台。

## 7. 热更新边界

- 安装包必须含可离线启动的基础内容和更新失败界面。
- 图片、音频、关卡、配置和本地化先实现资源热更新。
- C#代码热更新后置，候选方案为HybridCLR；资源管理候选为YooAsset，版本在Unity 6.6新工程建立后分别验证锁定。
- 下载到临时区，完整校验后原子切换；失败时保留上一份可用内容。
- `ClientVersion`、`ProtocolVersion`、`ContentVersion`分别管理，禁止混用。

## 9. 美术与已有素材

- 已有素材一律保留，不因玩法改版删除。
- 旧TapRise/Fall动作候选可作为漂移、闪避、受击或章节演出参考，不再代表物理状态。
- 背景必须通过横向无缝接缝检查；宽幅插画继续作为装饰或章节卡。
- 正式角色仍采用二次元Q版和统一线条/明暗语言。
- 一种语义状态一张透明主图；常态悬浮、后坐、淡出残影和轻摆由Unity表现层完成。

## 10. 工程纪律

- 用户操作Unity编辑器，Agent不手写场景、Prefab、Input Actions、程序集定义或Project Settings。
- 代码不自动添加组件、不查找场景对象、不用名称/路径推导玩法ID。
- 所有玩法数值和资源引用来自显式配置，缺失时明确报错并停用对应功能。
- 真人、AI和网络只产生统一角色命令，不能绕过权威战斗系统。
- 每轮仅实施一个可验证小步，未在Unity编译和Play Mode验证时只能报告“静态完成”。
