# 豆包密集迷宫实现与检查（2026-09-15）

> 2026-10-05 已修复跨句重叠：行距改为 2.36、最小句间隙 .12。原始实现和验收记录保留在下，最新结果见末节；旧行距 1.75 不再是现役值。

本轮源码/场景实现，不打包、不提交、不推送；不是整个大更新验收。

## 实现

- `DoubaoMazeRoute` 用种子生成相邻列连续路线，每 3 行允许转向一次。先保留通路，再放完整 3/4 字气泡组，不拆散词组填洞。
- 7 列，覆盖宽 19.2；气泡直径 1.24，组内偏移 x ±.6 / y ±.5，行距 1.75，下落 .85。路线保护半径 .75 大于现役玩家胶囊外接半径约 .49；组内不留可直接穿过的水平空隙。
- 实体和镜像池 240，低于快照 byte 数量上限 255；破裂特效池最大 288，预热仍 12，不一次性预热所有实例。
- Boss 活跃时每刷怪通道上限 3，与章节原上限取较小值；不清除已存在的小怪，结束/离段/重置/停用时解除。
- 气泡接触使用 `DamagePacket.SuppressKillReward`，在生命结算、敌人离场快照中传递；只按致命一击决定是否奖励。池化重生清除标记，普通击杀奖励保留。
- HS 刀刃/剑气伤害查询加入气泡层；索敌注册表不变。DS 米弹/HS 激光/敌弹既有路径未在本轮重写。
- 快照 40 使用现有可靠分片通道：240 个单字气泡的测试载荷 5784 字节，超过当前 NGO 非分片默认上限 1296；工程消息上限 16384。客户端先回收已消失 ID 再租新 ID，修复满池整体换行漏显示。
- 场景/配置由 `DoubaoMazeInstaller.Install()` 装配；内容版本 `20260915-doubao-maze-1`。

## 已执行检查

Unity 6000.6.0f1，通过 Boot → MainMenu → World01 Solo 进入 Play。

1. `DoubaoMazeChecks.RunGeometry()`：100 个种子共 6000 行、76700 个路线采样通过；每行 5—6 组，平均 5.48。几何检查，不等于玩家操作验收。
2. `RunPlay()`：180 秒、9000 次 2D 物理步进；峰值 150/240。Boss 出场、击败立即清墙、完成后不重启、重置、首波提前清除后仍出场均通过。为隔离测试关闭玩家/敌人接触；截图 `maze_20seconds.png`。
3. `RunInteractions()`：真实场景气泡接触处理函数 → 敌人死亡 → 钱包零奖励；池化复用后普通击杀奖励 1—5；刷怪上限；240 个同时破裂特效全部接受。接触回调人工注入，不是移动碰撞验收。
4. `RunMelee()`：3 招刀刃、3 招剑气实际物理查询均能伤害气泡。
5. `RunReplica()`：合成快照直接进入真实读取函数；240 镜像、全部换新 ID、旧帧丢弃、完成清空通过。未通过真实网络传输，不代表双端可靠性或延迟验收。
6. 最后读取 Unity Console：0 error / 0 warning。

## 2026-10-05 句间重叠修复

用户要求不同句子的气泡组之间略留距离。此前组高 2.24 大于行距 1.75，跨排最多重叠 .49；仅检验通路可通行没有发现句间排布问题。现在保留句内形状，把行距改为 2.36，句间最小净隙 .12，横向约 .303 不变，均小于玩家胶囊宽 .39，不新造可直接横穿的整排通道。

增加 MazeSentenceGap 配置和行/列跨度校验，运行时也检查裁到实际玩法宽度后是否容得下。MaximumGroupSize 改为按现役圆泡 Width 计算两个方向的直径。出生按预定时间补偿模拟步余量，先推进旧气泡，再放入补偿后的新排，避免同一步补发或固定步取整压缩间隔。首波到达时间仍按逻辑出生时间和距离计算。

使用 InstallSentenceSpacing 仅更新间距资产和内容版本，不重新装配场景或重置其他参数。网络内容版本为 20261005-doubao-gap-2；无打包、提交或推送。

最终检查通过：
