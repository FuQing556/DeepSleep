## 2. 已核实的现状及边界

### 2.1 复活与时钟

- `Configs/Players/CFG_PlayerReviveChannel_Default.asset`：自动起步延迟 0.2 秒、救援读条 2 秒、复活后保护 1.5 秒，复活生命为最大值三分之一且至少 1。
- `Simulation/FixedSimulationLoop.cs` 将 `Time.fixedDeltaTime` 传入 `PlayerReviveCoordinator2D.Simulate`；读条跟随缩放后的模拟推进。
- `Players/Health/PlayerDamageReceiver2D.cs` 的 `FixedUpdate` 用 `Time.deltaTime` 扣除无敌剩余时间。普通受击保护和复活保护共用计时字段，但已有 `_isReviveProtection` 区分来源。
- 普通受击无敌配置为 0.8 秒。本轮反馈没有明确要求改变这项，需单独决定，避免扩大修改。
- 因此“复活保护会被加速缩短”有代码依据；这轮未做设备计时复现，不能声称已完成动态验证。

### 2.2 HS 选敌与近战

- DS 与 HS 当前点选半径都是 0.8 世界单位，最大锁定距离为 20。
- `Combat/Targeting/ManualTargetFinder2D.cs` 使用范围查询，并以碰撞体到点击点的最近距离排序；没有高威胁分档。多个重叠碰撞体可能同为距离零，需要确定性的平局规则。
- `HarnessMeleeController.ReadAim()` 同时支持世界位置与方向。`TouchCommandSource.SetAimScreen()` 目前把触点转成世界位置；`TouchCommandPad` 只有移动摇杆，没有近战方向摇杆。
- 现有近战入场立即按当前朝向挥第一刀；后续持续攻击取决于 ConfirmAim 按住状态。PrimarySkill 在近战中承担退出请求。
- 近战当前归类为 Skill，激光归类为 PrimaryAttack。新手机提示和输入必须读取同一权限状态，不能仅按按钮文字判断封禁。

### 2.3 UI、权限书与角色表现

- 当前 `PlayerCombatHudSource` 已提供技能状态和剩余时间，可给技能键复用；不需要另起一套手机冷却计时。
- 共用设置的 `AudioSettingsPanel` 主要管理音量及云密度；应以现有入口改版，不能每加一个开关就继续在战斗主界面堆按钮。
- `ClaudePermissionModule2D.Corners` 引用四个世界坐标锚点。需要结合改版后的 HUD/摇杆占用区域重新安排。
- 权限书当前一、二阶段均 50 血，封禁 10 秒、预警 0 秒；召书后的技能休息 5 秒。移动书的位置不顺带修改这些规则。
- 已有 `SpritePoseTransition2D`、动作残影、受伤反馈和按姿态配置饰品的实现；DS 皮肤已有入场/节点等时机抽姿态的入口。新增动作应接入现有表现链，但它们并不等于完整的交互动作库。

### 2.4 安卓与隐私

- 版本为 Unity 6000.6.0f1，Input System 1.20.0。
- 本地最近构建的 Gradle Manifest 中，MAIN/LAUNCHER 指向 `UnityPlayerGameActivity`，没有 Unity 之前的独立隐私授权入口。
- Runtime 定向搜索未找到隐私同意流程；`Assets` 未检出自定义 AndroidManifest、Java/AAR/JAR 插件文件。
- `ProjectSettings.asset` 有 `accelerometerFrequency: 60`、`submitAnalytics: 1`；包列表包含 `com.unity.modules.unityanalytics`。这些是待审计线索，不能直接等同于已发生上传，也不能据此杜撰采集清单。
- 最近生成的 Manifest 含 INTERNET、ACCESS_NETWORK_STATE、ACCESS_WIFI_STATE、CHANGE_WIFI_MULTICAST_STATE。缺少敏感权限弹窗不代表没有传感器访问。
- 游戏存在局域网发现和联机中转路径，后续要按实际使用说明通信对象、数据和日志；不能把传感器问题直接判为联机导致。
- 尚未对受审 APK 做设备级 API 调用跟踪、网络抓包或审核复测。最终需要以实际包和平台检测结果确认。

## 3. 各项修改方案

### F01 简单模式

用户确认：局外菜单提供一个“简单模式”全局开关，控制所有可战斗关卡，包括测试场、两个世界和图鉴挑战；随时可在局外开关，持久保存。开局固定到本局，联机由房主决定、客机在准备页看到同一难度。局内不能切换以重置血量或奖励，不做每关各自的难度选择。

不复制简单版场景、Prefab 或整套 Boss。配置保存标准数值，开局生成本局难度参数；小怪、分裂子体、Boss、可破坏召唤物与次数盾在生成/重置时各应用一次。Boss 半血阈值跟随本局最大生命。血条、AI 对目标耐久的判断、任务、网络快照都读取实际值，禁止客机再次乘倍率。

| 项目 | 当前标准值 | 简单模式候选值 |
|---|---|---|
| 普通敌人及递归子体 | 对应波次的实际最大生命 | 波次加成后的生命 × 0.5，分裂层级不重复乘 |
| Kimi / Claude 本体 | 各 10000 HP | 各 5000 HP；2500 HP 转阶段 |
| Kimi 次数盾 | 300 / 500 次 | 150 / 250 次 |
| Kimi 镜框 | 600 / 1200 HP | 300 / 600 HP |
| Claude 权限书 | 50 / 50 HP | 25 / 25 HP |
| Claude 能量球 | 100 / 999 HP | 50 / 499.5 HP，沿用浮点生命 |
| 其他有血量的敌对召唤物 | 对应正式配置 | 最大生命 × 0.5 |

次数类若出现奇数，建议向上取整且至少 1；生命可使用现有浮点数，不把 3 血无意变成 1 血。Boss 常驻受击罩与 360 无敌盾不是可破坏血条，保持其判定和阻挡规则。

需要用户选定减半范围：

- 方案 A，建议先用：生命和破机制门槛减半；敌人伤害、弹速、刷怪、弹幕数量、封禁持续时间、预警和施法间隔保留。
- 方案 B：另减弹幕/召唤数量、封禁时长等攻击压力，需逐招做配置表；不能把预警、Boss 休息、大招蓄力时间一并砍半，那会反而减少玩家反应与破盾时间。
- 推荐奖励及原成就规则保持，记录本局难度供以后扩展；默认难度及是否限制简单模式成就由用户确认。图鉴原有收益/成就隔离必须保留。

验收：所有难度入口一致；递归每一级、Kimi 护卫、Boss 召唤物均只缩放一次；重新开始不继续减半；房主客机显示同血量；标准模式基线不变。

### F02 手机 UI 与菜单

1. 先用手机实际长宽比制定战斗安全区和操作区，不仅把整张 Canvas 放大。图标按有效画面大小验收，不能被透明留白“虚增尺寸”。
2. 主菜单保留开始、图鉴、装扮/商店、设置等主要入口；次要入口归组。局内一级菜单优先继续、设置、返回；设置分“操作 / 画面音效”，滑动显示，避免一屏挤满。
3. 技能按钮复用 HUD 状态源：中央倒计时、深色径向冷却遮罩、可用状态亮起。持续中显示持续状态，封禁覆盖优先于冷却，可同时保留小倒计时。
4. Claude 叉使用橙白几何切线和适度辉光，生成为独立透明素材，叠在移动摇杆、技能键及适当的攻击状态提示上。默认 DS/HS 风格按钮仍保留。
5. 手机没有独立远程普攻键，攻击封禁不能因此无提示：保留角色附近攻击权限球，并在本机角色 HUD 给出清晰图标。电脑也保留角色周围权限球。
6. HS 近战摇杆与退出按钮接 F08。封技能时近战摇杆显示封禁；普通攻击封禁按原权限语义处理，不能把近战也误封。退出近战应始终可用，避免玩家困在模式中。
7. 建议手机有效触摸目标以约 9–11 mm 为首轮目标，密集相邻按钮留明显间隔，再以真机手指操作检查；不把 Unity 单位或截图像素直接当作物理尺寸。
8. 给操作布局保留集中配置；首版可用整体 UI 缩放档位，不先扩展为复杂的自由拖拽编辑器。

验收：16:9、长屏和刘海安全区；双指移动与攻击；菜单不穿透点选敌人；冷却与主机一致；封禁、倒地、暂停、切模式不会留下旧叉或旧遮罩。

### F03 复活相关现实时间

建议自动救援起步 0.2 秒、救援读条 2 秒、复活保护 1.5 秒统一使用“不受场景倍率影响、但随本局暂停冻结”的时间。现实时间不等于退出到后台也继续消耗保护。

在现有模拟入口区分战斗模拟增量与未缩放的有效游戏增量，按系统需求传入；不要让各组件分别读取系统时钟、也不要简单把 FixedUpdate 中所有 deltaTime 全局替换。复活保护与普通受击保护分清来源，表现读同一剩余量。在线由权威端推进，客机显示快照；个人打开在线菜单若不会暂停房间，房间时间仍正常流逝。

用户接受最终沟通建议：普通受击 0.8 秒无敌也改为有效现实时间。保护时长数值先不加长，先修正计时语义。

验收：0.5×、1×、2×及叠加抵消下，实测读条/复活保护一致；暂停、后台、断线、重试和主客机显示一致；不能利用本地菜单冻结联网保护。

### F04 HS 自动攻击

设置页增加“HS 摆烂（自动激光）”，与完整 AI 托管区分。首版建议只负责自动选敌和激光循环，不移动、不自动救援、不自动开近战。

- 有手动锁定时优先手动目标；目标死亡、失效或玩家取消后恢复自动选择，不中途抢走正在瞄准的目标。
- 无手动目标时使用可配置的威胁分档和距离选择；加入稳定保持与重新评估时机，避免每帧换锁造成闪烁。
- 出场淡入、倒地、救援、封普攻、教程锁定步骤、结算等情况服从现有行动限制。
- 本机控制的角色使用本机偏好；离线 AI 队友沿用同伴策略，不被这个设置变成第二套 AI。
- 开关默认关闭、记住玩家选择为建议；可在教程结束后引导选择。

验收：手动覆盖有效；无目标不空转报错；目标出屏/池化重用不错误继承锁定；主机客机不重复开火；自动激光不抢救援或近战输入。

### F05 新手教程

教程应在输入和 UI 改版完成后接入，否则教学位置和交互会重复返工。

建议使用一套显式步骤配置，记录首次菜单、首次选 DS/HS、首次遇某敌种及首次遇机制的完成状态；可在设置重看/重置。按实际完成动作推进，不把点“下一步”当作学会锁定。

- 首次入游戏：介绍移动、角色差异和开局入口，提示难度可切换。
- DS：移动与自动攻击、手动点选、护盾、休息强化。
- HS：首次敌人出现时暂停危险推进，镜头轻微拉近；遮罩只给目标留窗，并保留本步必要的操作提示。必须通过原选敌链真正锁定，随后解除暂停。自动攻击与 AI 队友不得提前杀掉教学目标。
- HS 近战：技能切换、右侧攻击摇杆、左右独立操作、退出近战。
- 其他怪物：首次出现给短简介和关键应对；建议只有关键操作强引导，普通怪介绍可跳过，避免每波打断。
- Boss：首次遭遇介绍镜框/次数盾/权限书/能量球等关键交互，详解可从图鉴查看。
- 手机/电脑使用对应操作文案；镜头恢复后点选映射仍正确，缩放时背景不得露空。
- 强制暂停式教学建议只在离线首次教学使用；联机以非阻塞提示及局外练习为主，不能因一个新玩家教学暂停整房或只让一端停住。

验收：新档、老档迁移、跳过、重看和中途退出均可恢复；关闭自动攻击也能完成；教程不触发正式奖励/成就；从任意失败点退出不遗留相机、输入和时间限制。

### F06 随机与固定动作

先盘点 DS 默认、DS 工牌皮肤和 HS 现有可用姿态，再做素材表。需要补图时按已有母图生图，统一脸型、身高、朝向与透明规格，不能用攻击图硬当受伤或救援图。

候选首轮规模：每种外观补足 2–3 个可轮换常态/移动姿态，以及救援、受伤、强化、胜利动作；开技能优先复用已有专用动作，缺失的再补。具体张数由素材盘点决定，不承诺已有素材能覆盖全部事件。

- 随机变化在安全的动作切换点发生，建议 3–6 秒候选间隔、不连续抽到同姿态；不逐帧随机，不打断攻击。
- 行为、武器轨迹和碰撞不由图片决定；随机姿态仅改变表现。
- 固定动作由真实事件触发。倒地/结算、技能与攻击、救援、受伤、强化、常态之间列优先级，受伤可用短反馈叠加，不能把瞄准姿态强行换走。
- 饰品逐新姿态配置，皮肤也配套；特殊皮肤原有工牌露出/遮挡抽取规则保留，除非用户另改。
- 联机同步有意义的动作状态与变体；复用残影池，不为每张图新建一套角色控制器。

验收：技能/转向/救援取消/受击连续发生时不抖动抢图；饰品不飘移；镜像、倒地、节点及结算恢复正确。

### F07 辅助瞄准

独立设置“辅助瞄准”，建议默认开启。触摸半径使用屏幕/参考 UI 尺度换算，电脑可用较小范围，避免镜头和长屏使手指容错漂移。

建议顺序：明确点中可选目标时尊重精确点选；未点中时才在辅助圈内挑选。如果用户希望圈内高威胁连精确点选也能覆盖，需另行确认。

候选规则：只在圈内选可伤害且可锁定的目标；威胁明显更高才覆盖普通距离选择，同威胁层选离点击位置最近者。默认用碰撞轮廓到点击点的距离，重叠时再比较中心距离及稳定 ID。不要把“最近”误解为离 HS 最近。

威胁候选：即将撞到玩家的迅雷/快应用、正在限制玩家的权限书、逼近的能量球等可进入紧急档；Boss 不因名字始终压过紧急小怪，豆包气泡也不因可锁定就自动高优先。具体权重在同一配置集中管理，并复用已存在的感知信息。

辅助圈建议只在点击瞬间短暂显示；锁定标记明确显示最终选择。关闭辅助后采用精确点选，而不是保留隐形的大范围抢目标。

验收：密集递归、重叠碰撞体、高速目标、书/Boss 重叠、屏幕边缘及小半径鼠标点选；命中 UI 时不触发世界选择。

### F08 HS 近战攻击摇杆

采用用户新增方案。右侧原技能键的位置：激光模式显示技能键，近战模式显示方向攻击摇杆。退出近战键放右上 HUD 下方，位置依据控件安全区适当偏移，不机械地保持同一竖线。

建议操作规则：

- 左摇杆只控制移动；右摇杆拖动给出 360° 攻击方向，持续按住沿该方向连招，松手不再开始下一刀；已起刀完成原有结算。
- 在中心轻点/未拖出死区时，沿最近一次有效攻击方向；没有历史方向则沿当前朝向。新一刀取样方向，挥刀途中不强行扭转整条判定轨迹。
- 建议开近战只拔刀进入姿态，等玩家右摇杆输入再出第一刀；当前“入场自动朝当前方向挥一刀”是否保留须确认。
- 沿用 `AimIntent.Direction` 与原近战模拟，不额外制造手机武器。多人触点分别归属，移出摇杆边界继续持有，松开/失焦/切模式清理。
- 保持鼠标方向加按住攻击的电脑操作，分别写教程；移动反向场景 Buff 只反转移动，不反转攻击方向。
- 退出键始终可操作，包括技能被封或攻击键被按住时。模式到期、倒地、重试后按钮自动回到正确状态。

验收：左边缘朝左、右边缘朝右、四角斜砍；移动与攻击反方向；连招与剑气判定同向；禁用、断线或失焦没有持续自动挥刀。

### F09 权限书向中心收拢

保留四角分布和右侧书图镜像。先按统一战斗区域将四角锚点向中心收拢，首轮候选为相对中心的 X/Y 距离各保留 75%–80%；这只是初调范围，最终按新 UI 的实际遮挡检查。

关键限制：联机中书的位置属于玩法数据，不能让每台设备按自己的 UI 独立移动。采用跨设备都能看清和点到的共同世界位置，主机同步书坐标；手机 UI 应避让这些玩法区。测试书本可见轮廓、文字、身份球、底部光圈和点击范围一起是否被挡。

验收：四书同时出场，DS/HS、近战/激光、宽屏/长屏时均不被摇杆、技能键、退出近战键或 HUD 压住；不被移动到 Boss 护罩里导致难以击破；保留至少可达的攻击角度。

### F10 隐私整改

用户明确暂不计划上架，本项暂停，不作为本次游戏优化或出包的前置条件。以下仅保留以后恢复时的技术方案，不继续索取政策主体信息，也不将暂停标记为问题已修复。截图只能证明平台报告了上述两项，实际调用栈和 SDK 行为还需检测。

建议方案：Android 原生启动页面先展示本地可读的隐私摘要及全文入口，提供同意/拒绝；同意后再进入现有 Unity GameActivity。启动页本身不能先实例化 UnityPlayer。首屏读取本地政策避免在同意前为了加载文案就连接远端服务。

同意记录带政策版本；设置中可查看政策和第三方清单、撤回同意。政策实质更新后重新征求同意。拒绝时不启动相关引擎和服务，提供退出及重新阅读；拒绝后是否提供离线模式不能先承诺，因为本次报告涉及 Unity 引擎本身，而不只是联机功能。

实施检查范围：

1. 在项目内维护 Android 启动插件和确定性构建配置，不手改 Library 生成工程当作长期修复。
2. 审计 Application、ContentProvider、Service 与 Unity/其他 SDK 的自动初始化。前置 Activity 有效的前提是不存在更早的采集。
3. 检查传感器枚举与采样、输入设备注册、分析/崩溃服务；无实际用途的关闭或移除，同意后也不默认开启无关采集。Input System 设置及权限删改都需实际包验证，不能仅改一个开关宣布合规。
4. 梳理局域网广播、中转连接、IP/端口、房间标识、日志、本地存档以及外链；按实际数据流写政策，不抄别的游戏的长采集清单。
5. 单独说明 Unity 供应方、用途、实际信息类型与政策链接。若有第三方中转运营方，按实际共享关系披露。
6. 应用内政策、对外 HTTPS 页面和平台提交版本保持一致，开发/运营主体与联系方式由用户确认。未确认的信息不能编造或直接使用简历私人资料。
7. 原生首屏用简洁、易读的排版，可复用游戏色彩；不能为了做 uGUI 风格先启动 Unity。游戏内设置页仍使用 uGUI。

验收必须使用干净安装的正式安卓包：未选择、拒绝、同意、再次启动、撤回、政策更新、断网打开全文和后台恢复；检查同意前的设备 API 访问及网络行为，再交平台复测。修复这两项不等于承诺通过全部上架审核。

## 6. 补充讨论建议（未纳入已确认开发范围）

以下是进一步改善体验的建议，不因写进本文就自动开工：

- 战斗可读性：攻击预警、危险实体和玩家轮廓优先，装饰云、伤害跳字与己方大特效让出关键区域；可提供精简特效档，不改变伤害判定。
- 死亡原因反馈：显示最后一次实际伤害来源和简短应对，不先制作复杂战斗录像系统。
- 强化决策：卡片显示当前值到购买后的实际值、价格与升级等级；从基本输出/生存需求检查选项，避免新人漏买关键能力后整波崩盘。保留手动选择。
- 救援可见性：明确倒地位置、救援进度与复活保护剩余，危险预警仍可见；先用已确认的现实时间修正评估，不立刻叠加长时间无敌或全屏清怪。
- 进度节奏：现有波次内有压力起伏，Boss 招式间休息能从姿态和表现上被看懂；用试玩验证重叠压力，不机械地给所有敌人继续加血。
- 挑战重试：失败后减少重复菜单操作；若增加“相同构筑重试 Boss”，限定练习/图鉴并明确奖励边界，不默认给普通关卡增加检查点。
- 手机性能：针对递归大量分裂、全屏切割和多层能量球等峰值实测帧时间、内存和特效池；性能档优先降低装饰，不删除危险预警。尚无新性能测量，不宣称已有具体瓶颈。
- 演出克制：角色随机动作不覆盖攻击方向和技能状态，受击抖动/闪光可调，胜利和休息节点提供短暂情绪回落。

菜单候选结构：主页突出开始游戏、图鉴、装扮，设置为固定入口；商店/背包进入装扮页后分栏。联机随开始流程进入。局内一级保留继续、设置、返回主页；AI 托管、自动购买与战斗相关选项集中在操作页，难度只在局外可改。此结构用于讨论，具体现有入口映射在实现前逐项列清。
