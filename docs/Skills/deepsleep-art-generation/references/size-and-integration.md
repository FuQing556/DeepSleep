# 尺寸、画布、显示与判定分离

这些是 2026-09-08 工程核对和已确认规则，不是给所有图硬编码的常量。用户调参要保留；只在交付/接入需要时读取对应当前配置，不为单次生图扫描所有代码。

## 四种“大小”不能混用

1. 源图画布：PNG 分辨率，包含透明留白。
2. 可见轮廓：Alpha 可见包围盒；头发、尾巴、光晕会让其膨胀。
3. 身体标尺：头宽、躯干、腰线与锚点，跨姿态比较角色是否同一个大小。
4. Unity 显示与玩法：PPU、父级/视觉/姿态缩放、渲染代码；碰撞和伤害几何单独配置。

普通未旋转、未裁切的 Sprite 估算：`可见世界长 = 可见像素长 / PPU × 有效视觉缩放`。旋转后的轴对齐 bounds 会变大，不能拿它当身体真实变大。游戏预览估算：在 1080 高、10.8u 逻辑视野中，1u 约 100 个渲染像素；Editor Game 缩放/DPI 不等于实际输出分辨率。

## 当日事实与过期值

- 当前 DS 常态/睡眠、HS 常态/睡眠是 **1254×1254**；HS 激光姿态 **1280×1280**。均 PPU=512、中心 Pivot `(0.5,0.5)`、Bilinear、MipMaps 关闭，默认 Max Size=2048；平台覆写另查。
- 因此不把旧 `06_ArtAssetManifest.md` 的 320×320、PPU=100、旧 Pivot 当当前要求；也不把生成器偶然输出 1254 强行写成唯一合法分辨率。优先保留高分源图，必要时透明扩画布/整组等比规范化，保留变换记录；不破坏性压到 320。
- 统一画布并不能保证统一大小；导入时还需对齐身体核心与锚点语义。不能在每个坏姿态上堆临时隐藏补偿，也不能禁止用户有意设置的姿态倍率。
- `PF_Player_DeepSeek.prefab` 当日 `_aliveScaleMultiplier=1.05`、`_downedScaleMultiplier=1`；HS 两者为 1。历史讨论的 1.08 不是永久配置，禁止“纠正”回去。实时场景还可能有覆盖。
- `PlayerDownedVisual2D` 在 Awake 缓存 Visual 初始缩放，切姿态从基准乘各自倍率；Play 时改 Inspector 的局部缩放不一定持久生效。讨论尺寸先辨明是源图、视觉子节点还是脚本输出，不猜“改站姿必然同时改睡姿”。
- 旧规范约 2.45u 玩家、1.8×1.2u 404、1.8×1.3u 蛇只是首轮目标；角色头/身体与游戏观感优先，不能把所有含尾巴的轮廓强压成正方形。

## 命中特效的来源分类

| 对象 | 跟谁的倍率 | 不应改变的内容 |
| --- | --- | --- |
| DS/HS 攻击命中敌人 | Player | 敌人碰撞、生命、伤害范围 |
| 404/蛇攻击命中玩家 | Enemy | 玩家碰撞、实体尺寸 |
| 复活治疗加号 | Player | 粒子生成区域、救援判定范围 |
| 复活收束圈 | 不跟此倍率 | 表示进度，按独立尺寸配置 |
| 子弹、剑、激光攻击宽度 | 技能/强化自己的配置 | 不受可访问性命中特效选项驱动 |
| 炮口、死亡/睡眠图、本体 | 自己的表现尺寸 | 不受玩家/敌人命中特效倍率驱动 |

类别按来源，不按谁受伤。不要再使用容易反读的“玩家受击特效”指玩家造成的命中。

`Assets/_Project/Configs/Presentation/CFG_CombatEffectScale_Default.asset` 当日 Player=3、Enemy=1；可选范围0.5–5（50%–500%）。这是运行时视觉倍率，**不烘焙到 PNG、不改变碰撞体**。源图放大5倍再乘设置5倍属于重复缩放。

基础直径、时间缩放曲线、来源倍率共同影响画面。DS 当前命中配置 `_worldDiameter=0.64`；HS 由最小直径和光束宽度系数得基础大小，再乘时间曲线与 Player 倍率；不要只比较 PNG 分辨率就说相同大小。

治疗当日基准：收束圈直径3.0；三层加号生成圆盘半径1.65，中心随机落盘内，不只是沿圆周。粒子大小乘 Player 倍率、生成半径不乘；前中后三层是可控相对排序，不随机跨越整个世界/UI图层。详见 `docs/22_VisualScaleAndPoseTransitionSpec.md`，这些参数不是美术任务自动修改项。

## 渲染接入交接

- 普通等比视觉缩放允许；不要缩放物理根，不改变用户碰撞体来让美术“看着对”。
- 普通位图禁止非等比拉伸；九宫格边框、明确可循环中段使用对应 Sliced/Tiled。HS 最终激光束体按既定动态网格+X方向重复UV，不改成整图拉长或 LineRenderer 占位。
- HS 激光炮口从角色前方锚点出现，瞄准/蓄力至发射阶段持续；左右朝向共用角色决定的方向。画图不应把光束起点固定烘在身体中心。
- Y 排序、Sorting Group 与内部 Order 要兼容；Sorting Layer、Physics Layer、URP Rendering Layer 是不同概念。当前角色 Gameplay 组Order20，DS/HS命中Prefab Gameplay Order60只是核对样例；MeshRenderer可能由脚本复制排序，不能仅看序列化Default就认定BUG，也不能让用户找并不存在的Inspector字段。
- 新姿态立即显示，旧图半透明跟随实体平移淡出，保留旧旋转/翻转/尺寸；不把残影画在人物主图里。
- 导入前记录PNG尺寸/可见轮廓、PPU、Pivot、锚点、Facing、Sorting及是否循环。用 Unity 途径接入，不手写 `.meta`、Prefab/Scene YAML；生图验收不等于Unity实测通过。
